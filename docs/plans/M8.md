# M8-local plan: unpacked Chrome extension (activeTab only)

Status: draft for plan-reviewer (autopilot, decision 27).

## Context

BUILD_PLAN "M8-local" (decision 21): ReadLayer on any news page, loaded unpacked (Developer
mode), not on the Web Store. Permissions `activeTab`, `scripting`, `storage` only; no host
permissions, no content scripts in the manifest, nothing runs until the reader clicks the toolbar
button. On click: refuse sensitive pages, extract the article with Readability on a DOM clone,
redact client-side, send only title + paragraphs, and overlay the shared annotator
(`packages/annotator`) on the live page. Auth comes from the web app ("Connect extension") for
demo and Google readers. The demo video can then show the overlay on a real publisher page.

Date: Oct 14 in the schedule; starting Oct 10. Code freeze Oct 16.

## A. API

1. **Two-phase submitted text.** `SubmittedRequest` gains `defer: bool = False`. With
   `defer: true`, POST /v1/content stores the extracted, redacted paragraphs as a
   `pending_contents/` doc (source `extension`) and returns `{content_id, status: "analysing"}`
   at once; the extension then calls the existing POST /v1/content/{id}/analyse (lease, timeout,
   attempts as in M6). Without `defer`, behaviour is unchanged. Same ingest caps (20/day; 3/day
   per anonymous uid, 30 shared), pending/known URLs free.
2. **Server-side PII backstop** on the submitted path only (`app/privacy/pii.py`):
   - Presidio `AnalyzerEngine` with the spaCy model already in the image (`en_core_web_sm`, via
     `NlpEngineProvider`), entities EMAIL_ADDRESS, PHONE_NUMBER, CREDIT_CARD, IBAN_CODE, plus
     custom regex recognizers for Aadhaar and PAN. Lazy import (ingestion path only, like
     trafilatura), so read paths and cold start are unchanged.
   - If PII findings exceed **5 per 1,000 words** (or any page with ≥ 3 card numbers), refuse:
     422 `personal_data` "This page looks like it holds personal information, so ReadLayer won't
     read it." Below the threshold, `app/privacy/redact.py` runs on every paragraph before
     storing (defence in depth on top of the client's redaction).
   - Presidio adds `presidio-analyzer` (pinned) to the API; no new model download.
3. **CORS:** `CORS_ORIGINS` adds the extension origin `chrome-extension://<id>`. The id is
   stable because the manifest carries a public `key` (generated once; the private key is not
   needed for unpacked loading and is not kept). The extension's background worker is the only
   caller; content scripts never call the API.
4. No new Firestore collection; no LLM on the annotations path; extension-ingested docs use
   source `extension` (already excluded from corpus and held-out builds? **check and exclude**
   like `user_ingested`).

## B. Extension (`apps/extension`)

1. **Manifest (MV3):** permissions `activeTab`, `scripting`, `storage`; **no** `host_permissions`,
   **no** `content_scripts`; `externally_connectable.matches` = the two Hosting origins (+
   `http://localhost:5173/*` in the dev build only); `action` with a popup; public `key`.
2. **Background service worker (`background.ts`):**
   - `chrome.action` opens the popup; the popup's "Read this page" (and a keyboard shortcut,
     `_execute_action`) triggers `readActiveTab(tabId)`.
   - Injects `content.js` with `chrome.scripting.executeScript` (activeTab grants the current tab
     only), receives `{url, title, paragraphs}` or `{refused: reason}`.
   - All API calls (content, analyse, annotations, explain, events, corrections) go through the
     worker with the bearer token; the content script talks to it with `chrome.runtime` messages.
   - Tokens: `idToken` + `refreshToken` + expiry in `chrome.storage.session` only (cleared when
     the browser closes; never `storage.local`). Refresh via Firebase's securetoken REST endpoint
     (the Auth emulator's in the dev build). Never logged.
3. **Content script (`content.ts`, IIFE bundle, injected on click only):**
   - **Refusals (before reading anything):** any `input[type=password]`, any
     `autocomplete^="cc-"` input, URL patterns for mail (mail.google.com, outlook.live.com,
     outlook.office.com, mail.yahoo.com, proton.me), banking (`/bank|netbanking|ibanking/`
     in host, known bank domains list), intranet (non-public TLDs `.local`, `.internal`, `.corp`,
     `.lan`, localhost and private IPs) and `chrome://`/file URLs. Refusal shows a quiet toast.
   - **Extraction:** `@mozilla/readability` (pinned) on `document.cloneNode(true)`; paragraphs
     from the extracted HTML's block text (`p`, `li`, `blockquote`, headings excluded), min
     length as the API's `clean_paragraphs`; title from Readability. Never raw HTML, comments
     or form fields.
   - **Client redaction** (`redact.ts`, same patterns as `app/privacy/redact.py`, Luhn for card
     runs): emails, phones, card-like digit runs, Aadhaar, PAN → `[REDACTED:type]`. The API
     receives redacted text only; a vitest pins the patterns against the Python ones' fixtures.
   - **Mounting:** tags the live page's paragraphs (`data-rl-paragraph="pN"`) by matching each
     extracted paragraph's normalised text to a live block element (exact, then prefix match);
     the article text is never changed. Mounts `createAnnotator(articleRoot, …)` on the common
     ancestor of the tagged paragraphs; spans, markers, the "Know this?" chip, dwell/text-search
     signals, explanations (via the worker) and the pre-read card (inserted before the first
     tagged paragraph as `data-rl-ui`) all reuse the M6/M7 annotator.
   - Two-phase: "Reading this page…" toast while phase 1 runs, the overlay appears when the
     analysis finishes (poll analyse with the 202 retry, up to 180 s), "Notes are ready" toast.
4. **Popup (`popup.html/ts`):** sign-in state (Google name, or "Demo · <persona>"), "Read this
   page", persona picker for demo readers, density (minimal / balanced / guided), "Open your
   reading profile" link, "Connect" link when signed out. Keyboard and screen-reader usable.
5. **Build:** two Vite builds (ES for worker/popup, IIFE for the content script), env-driven
   API base and Firebase web key (`make extension-config` writes `.env` from the web config),
   `pnpm --filter extension build` → `dist/` ready for "Load unpacked". A build check fails if
   the manifest gains host permissions or content scripts.

## C. Web: "Connect extension"

`/connect` page (signed-in or demo): explains what the extension can see; "Connect" sends
`{idToken, refreshToken, expiresAt, persona?}` to the extension id via
`chrome.runtime.sendMessage` (only works from the allowed origins); shows connected / not
installed states. Demo readers connect as their demo session (same anonymous uid).

## D. README

"Install the extension locally": build or download `dist`, chrome://extensions → Developer mode →
Load unpacked → pin → open the web app's Connect page → open a news article → click ReadLayer.

## Data rights, privacy, cost

- No new user collection. Extension-ingested content is shared content (`contents/`,
  `pending_contents/`, source `extension`), no uid stored with it. Events/explanations/corrections
  go to the existing user-data paths (export/delete covered).
- Only redacted article text leaves the browser; never URLs of refused pages, form fields or
  raw HTML. The token never reaches the page or the content script.
- Anonymous cost: unchanged caps (3 new pages per uid per day, 30 shared; explain caps).
- Presidio runs only on extension submissions (CPU, no per-call cost).

## Tests (offline)

- pytest: `defer` path stores pending only (no LLM), analyse completes it; PII backstop refuses
  above the threshold and redacts below it (fixtures); Presidio import is lazy (read paths don't
  import it); extension source excluded from corpus selection; CORS allows the extension origin
  when configured.
- vitest (`apps/extension`, jsdom): refusal rules (password field, cc input, mail/bank/intranet
  URLs), Readability extraction on saved fixtures of 3 news pages (no network), redaction
  patterns, paragraph tagging leaves `textContent` unchanged, message protocol.
- Manifest check: no host permissions, no content scripts.

## Acceptance (BUILD_PLAN M8-local)

1. Works on 3 news sites without site-specific code, for a demo reader and a Google reader:
   headless Chrome with `--load-extension=dist` on the local emulator harness (emulator Google
   reader), triggering the worker's `readActiveTab` through CDP (a headless browser has no
   toolbar), on 3 live public news pages (fetched by the browser, ingested into the **emulator**):
   spans and markers render, a card opens with a verified explanation. Screenshots.
2. Does nothing until clicked; on click refuses on a Gmail tab, a bank login page and a page with
   a password field: unit tests for the rules + harness runs on a local password test page and on
   mail/bank URL fixtures (no logging into anything).
3. A test page with an email and a phone number in the article body arrives server-side
   redacted: local test page through the harness; the stored pending/contents doc shows
   `[REDACTED:email]` / `[REDACTED:phone]`.
4. `manifest.json` lists no host permissions and no content scripts (build check + review).
