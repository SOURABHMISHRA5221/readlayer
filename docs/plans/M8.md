# M8-local plan: unpacked Chrome extension (activeTab only)

Status: **amended 2026-10-12** for plan-reviewer (autopilot). The 2026-10-10 plan was approved
(round 2) and then paused for M2.2, M7.5, the Design pass, Landing and onboarding, decisions 48
and 50. This amendment rebases it on today's `main` (0ba30e1). Changes against the approved
plan are marked **[amended]**; everything else stands as approved.

## Context

BUILD_PLAN "M8-local" (decision 21): ReadLayer on any news page, loaded unpacked (Developer
mode), not on the Web Store. Permissions `activeTab`, `scripting`, `storage` only; no host
permissions, no content scripts in the manifest, nothing runs until the reader clicks the toolbar
button. On click: refuse sensitive pages, extract the article with Readability on a DOM clone,
redact client-side, send only title + paragraphs, and overlay the shared annotator
(`packages/annotator`) on the live page. Auth comes from the web app ("Connect extension") for
demo and Google readers. **[amended]** A Google reader who hasn't finished onboarding is sent to
the web app's 2-screen onboarding (decision 41) before anything is read. The demo video can then
show the overlay on a real publisher page.

Order (decision 49): d50 (done) → **M8-local** → Wide layout. Dates: build Oct 12–14, code
freeze Oct 16. **Checkpoint end of Oct 13 IST:** the extension annotates one live news page on
the emulator harness. If not, stop and ask Sourabh what to cut (decision 27); candidates, in my
suggested order: popup density control → Presidio (keep the regex backstop only) → paragraph
markers in the extension.

## A. API

0. **[amended] Carry-over from 2f037a1 (first commit on the branch).**
   - `app/privacy/redact.py`: placeholders become `[REDACTED:email|phone|card|aadhaar|pan]`
     (DESIGN §11.3's format, shared with the extension); patterns need a real shape (cards: 13–19
     digits grouped 4-4-4-x or ungrouped, Luhn; Aadhaar: 4-4-4 with spaces, first digit 2–9;
     phones: `+cc …`, Indian mobile 0?[6-9]xxxx xxxxx, or bracketed area code) so news figures,
     dates and year ranges survive; `count_redactions(text)`.
   - `tests/fixtures/redaction.json` (7 redact cases, 10 unchanged news lines) +
     `tests/test_redact.py`; the extension's vitest reads the same file.
   - Callers that redact reader-typed text (profile edit, goals, onboarding) keep working; their
     tests' placeholder assertions move to the new format (`test_profile_edit`,
     `test_onboarding_flow`, `test_goals`). Behaviour note: the stricter patterns redact fewer
     false positives in typed text (e.g. "2019-2020-2021" no longer becomes an id).
   - `is_corpus` in `scorer.explainer_index`, `build_concepts.select_corpus` and
     `eval_heldout.heldout_docs` (each with a test using an `extension` doc).
1. **Two-phase submitted text.** `SubmittedRequest` gains `defer: bool = False`. With
   `defer: true`, POST /v1/content stores the cleaned, redacted paragraphs as a
   `pending_contents/` doc (source `extension`) and returns `{content_id, status: "analysing"}`
   at once; the extension then calls the existing POST /v1/content/{id}/analyse (lease, timeout,
   attempts as in M6). Without `defer`, behaviour is unchanged. Same ingest caps (20/day; 3/day
   per anonymous uid, 30 shared), pending/known URLs free, growth slots reserved as today.
   **[amended]** The deferred path calls `add_ingested(uid, content_id)` before returning, like
   the synchronous one, so the page shows in the submitter's library while it is analysing and
   after. If the URL is already a corpus doc, that doc is returned (`status: "ready"`), the
   submitted text is discarded, and `add_ingested` is harmless (corpus docs are never hidden).
2. **Server-side PII backstop** on the submitted path only (`app/privacy/pii.py`):
   - Presidio `AnalyzerEngine` with the spaCy model already in the image (`en_core_web_sm`, via
     `NlpEngineProvider`; loaded once per process, lazily), entities EMAIL_ADDRESS,
     PHONE_NUMBER, CREDIT_CARD, IBAN_CODE, plus custom regex recognizers for Aadhaar and PAN.
     Lazy import (ingestion path only, like trafilatura), so read paths and cold start are
     unchanged.
   - If PII findings exceed **5 per 1,000 words** (or any page with ≥ 3 card numbers), refuse:
     422 `personal_data` "This page looks like it holds personal information, so ReadLayer won't
     read it." Quota refunded. Below the threshold, `redact()` runs on every paragraph before
     storing (defence in depth on top of the client's redaction).
   - Presidio adds `presidio-analyzer` (pinned) to the API; no new model download.
3. **CORS:** `CORS_ORIGINS` adds the extension origin `chrome-extension://<id>`. The id is
   stable because the manifest carries a public `key` (generated once; the private key is not
   needed for unpacked loading and is not kept). The extension's background worker is the only
   caller; content scripts never call the API.
4. **[amended] Onboarding gate (server backstop).** POST /v1/content with a *submitted* body
   from a non-anonymous caller whose onboarding isn't done → 409 `onboarding_required` (no quota
   reserved, nothing stored). One profile read, on this path only. Demo readers are never
   gated. URL bodies (scripts, web) are unchanged.
5. No new Firestore collection; no LLM on the annotations path. Extension docs are NOT_CORPUS
   (point 4 of "What has changed").

## B. Annotator 0.8.0 [amended]

Additive, so the web app is unaffected:
- `AnnotatorOptions.styles?: "inject" | "external"` (default `"inject"`, today's behaviour).
  `"external"`: the host has already applied the CSS; `injectStyles` is skipped.
- Export `ANNOTATOR_CSS` (the string `injectStyles` uses). The extension's worker applies it
  with `chrome.scripting.insertCSS` (activeTab), which a publisher's CSP can't block, unlike a
  `<style>` element inserted by a content script.
- `ANNOTATOR_VERSION` and `package.json` both → 0.8.0. vitest: `"external"` inserts no style
  element; default unchanged.
- If the 3-site harness shows publisher CSS bleeding into the card (button/paragraph resets),
  scoped resets go into `ANNOTATOR_CSS` under `.rl-card` (and are re-checked on the web reader).

## C. Extension (`apps/extension`)

1. **Manifest (MV3):** permissions `activeTab`, `scripting`, `storage`; **no** `host_permissions`,
   **no** `content_scripts`; `externally_connectable.matches` = the two Hosting origins (+
   `http://localhost:5173/*` in the dev build only); `action` with a popup; public `key`.
2. **Background service worker (`background.ts`):**
   - `chrome.action` opens the popup; the popup's "Read this page" (and a keyboard shortcut,
     `_execute_action`) triggers `readActiveTab(tabId)`.
   - **[amended] Before injecting anything**, for a Google reader: GET /v1/me/profile; if
     `onboarding.done` is false, nothing is injected and the popup shows "Finish setting up
     ReadLayer first" with a button opening the web app's `/welcome` in a new tab (the web
     router already lands there). The result is cached for the worker's life and re-checked on
     the next click while it's false. Demo readers skip the check.
   - Inserts `ANNOTATOR_CSS` (`insertCSS`), then injects `content.js` with
     `chrome.scripting.executeScript` (activeTab grants the current tab only), receives
     `{url, title, paragraphs}` or `{refused: reason}`.
   - All API calls (content, analyse, content detail, annotations, explain, events, graph
     answers, settings) go through the worker with the bearer token; the content script talks to
     it with `chrome.runtime` messages. Demo readers' calls carry `?persona=`.
   - Tokens: `idToken` + `refreshToken` + expiry in `chrome.storage.session` only (cleared when
     the browser closes; never `storage.local`). Refresh via Firebase's securetoken REST endpoint
     (the Auth emulator's in the dev build). Never logged.
3. **Content script (`content.ts`, IIFE bundle, injected on click only):**
   - **Refusals (before reading anything):** any `input[type=password]`, any
     `autocomplete^="cc-"` input, URL patterns for mail (mail.google.com, outlook.live.com,
     outlook.office.com, mail.yahoo.com, proton.me), banking (`/bank|netbanking|ibanking/`
     in host, known bank domains list), intranet (non-public TLDs `.local`, `.internal`, `.corp`,
     `.lan`, localhost and private IPs) and `chrome://`/file URLs. Refusal shows a quiet toast.
   - **Extraction:** `@mozilla/readability` (pinned) on `document.cloneNode(true)`; paragraphs
     from the extracted HTML's block text (`p`, `li`, `blockquote`, headings excluded), min
     length as the API's `clean_paragraphs`; title from Readability. Never raw HTML, comments
     or form fields.
   - **Client redaction** (`redact.ts`, same patterns as `app/privacy/redact.py`, Luhn for card
     runs) → `[REDACTED:type]`. The API receives redacted text only; a vitest runs
     `apps/api/tests/fixtures/redaction.json` against `redact.ts`.
   - **Mounting [amended]:** after the analysis is ready, the worker fetches GET
     /v1/content/{id} and the content script tags live elements against the **server's**
     paragraphs and ids (they may differ from what was sent: `clean_paragraphs`, the server
     redaction, or a corpus doc already stored for that URL), matching normalised text (exact,
     then prefix) to a live block element; unmatched paragraphs get no notes. Article text is
     never changed. Mounts `createAnnotator(articleRoot, { styles: "external", actions: "full",
     onEvent, onAnswer, loadExplanation })` on the common ancestor of the tagged paragraphs (no
     `loadShifted`, no `sidenote`: popover and bottom sheet). Spans, markers, the "Know this?"
     chip, dwell/text-search signals, explanations (via the worker) and the pre-read card
     (inserted before the first tagged paragraph as `data-rl-ui`) all reuse the annotator.
   - Two-phase: "Reading this page…" toast while phase 1 runs, the overlay appears when the
     analysis finishes (poll analyse with the 202 retry, up to 180 s), "Notes are ready" toast.
     Errors (cap reached, `personal_data`, 410, timeout) show the API's message in the toast.
4. **Popup (`popup.html/ts`):** sign-in state (Google name, or "Demo · <persona>"), "Read this
   page", persona picker for demo readers, density (minimal / balanced / guided, PATCH
   /v1/me/settings), "Open your reading profile" link, "Connect" link when signed out,
   **[amended]** "Finish setting up" state. Keyboard and screen-reader usable; light and dark
   follow `prefers-color-scheme` with the Gloss tokens.
5. **Build:** two Vite builds (ES for worker/popup, IIFE for the content script), env-driven
   API base and Firebase web key (`make extension-config` writes `.env` from the web config),
   `pnpm --filter extension build` → `dist/` ready for "Load unpacked". A build check fails if
   the manifest gains host permissions or content scripts.

## D. Web: "Connect extension"

`/connect` page (signed-in or demo): explains what the extension can see; "Connect" sends
`{idToken, refreshToken, expiresAt, persona?}` to the extension id via
`chrome.runtime.sendMessage` (only works from the allowed origins); shows connected / not
installed states. Demo readers connect as their demo session (same anonymous uid).
**[amended]** `/connect` is a normal route under the existing gate, so an unfinished Google
reader is sent to `/welcome` first; it is added to the returnable routes so a signed-out visit
comes back to it after sign-in. Linked from the profile page.

## E. README

"Install the extension locally": build or download `dist`, chrome://extensions → Developer mode →
Load unpacked → pin → open the web app's Connect page → open a news article → click ReadLayer.

## Data rights, privacy, cost

- No new user collection. Extension-ingested content is shared content (`contents/`,
  `pending_contents/`, source `extension`), no uid stored with it; the submitter's link to it is
  the existing `ingested` list (already in export and delete, M7.5). Events, explanations,
  answers and corrections go to the existing user-data paths.
- Only redacted article text leaves the browser; never URLs of refused pages, form fields or
  raw HTML. The token never reaches the page or the content script.
- Anonymous cost: unchanged caps (3 new pages per uid per day, 30 shared; explain caps).
- Presidio runs only on extension submissions (CPU, no per-call cost).
